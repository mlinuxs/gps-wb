# 锂安 BMS + 途强 GPS ESP32 程序

由微信小程序（锂安BMS）源码逆向移植的 Python 实现：ESP32 通过蓝牙连接电池保护板，
读取电压 / 电流 / SOC / 温度 / 电芯电压 / 报警状态等全部数据；
同时通过 UART1 串口读取途强定位器的 $GNRMC 语句，解析经纬度 / 速度，一并显示。

## 文件说明

| 文件 | 运行环境 | 作用 |
|---|---|---|
| `bms_protocol.py` | ESP32 | 协议层：CRC、帧构造/解析、寄存器解码（纯 Python） |
| `bms_ble.py` | ESP32 (MicroPython) | BLE 驱动：扫描 / 连接 / 服务发现 / 订阅通知 / 分片写 |
| `bms_client.py` | ESP32 (MicroPython) | 事务层：请求-应答、超时重试、分片读（单次最多 8 寄存器） |
| `gps_nmea.py` | ESP32 (MicroPython) | 途强 GPS：UART1 读取 + $GNRMC 解析（非阻塞） |
| `main.py` | ESP32 (MicroPython) | 主程序：BLE 读 BMS + UART 读 GPS，循环打印/输出 JSON，掉线重连 |

## 电脑直连（无需 ESP32）

`main.py` 会自动检测运行环境：电脑上没有 `ubluetooth`，会改用 `host_demo.py`（bleak）
读同一块 BMS，协议层与 ESP32 完全共用：

```bash
pip3 install bleak
cd esp32_bms
python3 host_demo.py --scan                        # 只扫描，列出附近所有设备
python3 host_demo.py --probe                       # 逐台连接探测：谁含 2760 服务就读谁
python3 host_demo.py --addr <设备UUID> --rounds 3  # 已知地址直连（最稳，跳过扫描）
```

> **实测坑：这块保护板既不广播设备名，也不广播 2760 服务 UUID。**
> 它在扫描列表里就是一个**名称为空**的设备，而且广播是**间歇的**
> （10 秒的扫描窗口可能刚好漏掉，15 秒才抓得到，RSSI 约 -65）。
>
> 微信小程序能连上，是因为它"先全量扫描、连接后再用 `getBLEDeviceServices`
> 找 2760 服务"（`utils/ble.js`），且名称为空的设备也允许手动点连
> （`pages/bind/bind.js` 里显示为"未广播名称"）。
>
> 所以电脑端**不能只按名称/广播 UUID 过滤 BMS**——请用 `--probe` 逐台探测，
> 或记下设备 UUID（macOS/CoreBluetooth 对同一设备基本固定）后用 `--addr` 直连。
>
> 另外：若手机上的小程序**正连着**这块 BMS，它会停止广播/拒绝新连接，
> 此时电脑既扫不到也连不上，需先在小程序里断开。

## 部署到 ESP32

1. ESP32 刷入 MicroPython 固件（≥ v1.20，esp32 端口通用版即可）
2. 用 Thonny / mpremote / ampy 把 5 个文件上传到 ESP32 根目录：

```bash
# 方式 A: mpremote（推荐）
pip3 install mpremote
mpremote cp bms_protocol.py bms_ble.py bms_client.py gps_nmea.py main.py :

# 方式 B: Thonny → 工具 → 选项 → 解释器选 ESP32，直接另存为到设备
```

3. 复位（或 `mpremote soft-reset`），程序自动运行，串口监视器（115200）查看输出：

```bash
mpremote
# 或: screen /dev/ttyUSB0 115200
```

## 接线

| 设备 | 引脚 |
|---|---|
| 途强 GPS TXD | → ESP32 GPIO5（UART1 RX） |
| 途强 GPS RXD | ← ESP32 GPIO4（UART1 TX，可不接，占位） |
| 波特率 | 115200，8N1 |

`main.py` 顶部可配置：
- `TARGET_NAME`（指定目标板名称，如 `'LABMS-46191G38155'`，多块保护板时只连这一块）
- `SLAVE_ADDR`（从机地址）、`POLL_INTERVAL_S`（轮询间隔）
- `JSON_ONLY=True`（只输出 JSON 行，GPS 数据合并进 `"gps"` 字段，便于 MQTT / HTTP 上报）
- `GPS_ENABLED`（False 则禁用 GPS）、`GPS_RX_PIN`（默认 5）、`GPS_TX_PIN`（默认 4）、`GPS_BAUD`（默认 115200）

## 协议要点（从小程序逆向）

| 项目 | 值 |
|---|---|
| BLE 服务 | `00002760-08C2-11E1-9073-0E8AC72E1001` |
| 写特征 | `00002760-08C2-11E1-9073-0E8AC72E0001`（带响应写） |
| 通知特征 | `00002760-08C2-11E1-9073-0E8AC72E0002` |
| 从机地址 | 22 (0x16) |
| 帧格式 | `[地址][功能码][数据…][CRC低][CRC高]` |
| CRC | **CRC-16/XMODEM**（poly 0x1021，初值 0x0000，低字节在前）——不是标准 Modbus CRC！ |
| 读寄存器 | 功能码 0x03，单次最多 8 个，分片间隔 30ms |
| 写寄存器 | 功能码 0x10（部分寄存器需先通过 4 位数字密码解锁，本程序只做读取） |

## 寄存器映射（实时数据区）

| 寄存器 | 内容 | 格式 |
|---|---|---|
| 0 | MOS 温度 | u16，0.1K |
| 1–3 | 温度 1–3 | u16，0.1K |
| 4–5 | 总电压 | u32，mV |
| 6–7 | 电流 | i32，mA（正=充电，负=放电） |
| 8–9 | 剩余容量 | u32，mAh |
| 12–13 | 状态位 | u32（bit16 放电 MOS，bit17 充电 MOS） |
| 14 | 报警位 | u16（bit0 超高压 … bit6 压差过大） |
| 15 | 电池包状态 | u16（bit8 满充，bit15 固件未解锁 等） |
| 19 | 固件版本 | u16（高字节主版本，低字节次版本） |
| 20 | SOC / SOH | 低字节 SOC%，高字节 SOH% |
| 21–23 | RTC | 基准年 2022 + 寄存器 21 高字节 |
| 24 | 电芯串数 / 类型 | 高字节串数；低字节 0 铁锂 / 1 三元 / 2 钛酸锂 / 3 钠电 |
| 26 | 循环次数 | u16 |
| 27 | 满充容量 | u16 ×10 mAh |
| 28 | 设计容量 | u16 ×10 mAh |
| 30–31 | 运行时长 | u32，秒 |
| 32 起 | 各电芯电压 | u16，mV |
| 560 起 (0x0230) | SN / 厂商 / 型号 / 客户信息 | ASCII，42 regs |
| 1024 起 (0x0400) | 循环次数 / 满充容量 / 闲置时长 / BT 码 | 0x0401 u16 循环、0x0402 u32 满充、0x0408 起 BT 码 |
| 2052 起 (0x0804) | BMSID | ASCII，12 regs |
| 512 起 | 参数区（保护电压/电流阈值等） | 详见小程序 utils/registers.js |

## 常见问题

- **Thonny 报 `Device not configured` / USB 掉线**：多为供电不稳或 USB 干扰——
  1. 给 ESP32 用**外部 5V 供电**（充电头/充电宝），电脑 USB 只做串口；
  2. 换一根好线、换一个 USB 口；3. BLE 运行时串口偶尔掉线属正常，按板子 RESET 键即可恢复。
- **建议用串口监视器而不是 Thonny「运行」**：Thonny 后台会不停探测 REPL，
  BLE 扫描时容易冲突报错。推荐做法：用 Thonny 上传 4 个文件后**关闭 Thonny**，
  按 RESET 键让板子自动运行 main.py，再用 `mpremote` / `screen` 看输出：
  ```bash
  mpremote                     # 或 screen /dev/ttyUSB0 115200
  ```
- **扫描看不到进度/疑似卡住**：新版本每 2 秒会打印「扫描中... 已发现 N 台设备」，
  能看到进度说明程序正常，只是附近没有目标 BMS。
- **扫描不到设备**：确认保护板已上电、蓝牙在广播。
- **GPS 一直显示「等待卫星定位」**：到室外空旷处等待；确认途强 TX → GPIO5 接线正确、
  波特率 115200；可用串口工具先验证 GPS 单独输出。
- **连接后读数据超时**：多为 MTU 问题——若 MicroPython 固件较老不支持 `config(mtu=)`，
  升级到 v1.20+；本驱动已做 20 字节分片写 + 通知分片累积，仍可工作。
- **响应起始地址不匹配**：说明 BMS 返回了扩展格式帧且地址异常，程序会抛错并自动重连。
- **多块保护板**：`main.py` 顶部设 `TARGET_NAME = 'LABMS-46191G38155'`（或任意名称关键字）
  即可锁定目标板；不设置则自动连信号最强的一块。从机地址不同可通过 `SLAVE_ADDR` 区分。
