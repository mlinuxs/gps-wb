# 2026-08-23 工作日志

## 锂安 BMS ESP32 读取程序：BMS 响应超时问题修复（已解决）

**现象**：BLE 连接/订阅成功，但所有 Modbus 读寄存器请求超时，循环重连。

**三层根因（全部在 bms_ble.py + bms_protocol.py + bms_client.py 修复）**：
1. **写通道选错**：BMS 只响应 write-without-response 特征（value=0x0023, props=0x04）的无响应写（mode=0），与电脑端 bleak 的 `response=False` 一致。原代码用 props=0x0A 的 0x0003 特征 + mode=1（带响应写），BMS 完全无视。
   - `_find_chars` 改为：写特征优先 props&0x04（write-no-rsp），其次 0x08；通知特征 props&0x10（value=0x0026）。
   - `write()` mode 改为 `0 if (props & 0x04) else 1`，mode=0 不等待 WRITE_DONE。
2. **MTU 从未协商**：只 `config(mtu=185)` 不生效。必须连接后调 `ble.gattc_exchange_mtu(conn_handle)`。否则 MTU=23，>20B 的响应帧（如 23B 的读 8 寄存器响应）被拆包且第二片丢失 → CRC 失败 → 超时。协商后 `_write_chunk=182`。
3. **固件 IRQ 异常兼容**（ESP32-C3 v1.28.0）：
   - 特征/描述符 uuid 全返回同一个假值（16 个特征 uuid 均为 02002e...），**不能按 UUID 匹配特征**，必须按 props。
   - `_IRQ_GATTC_NOTIFY` 的 notify_data 可能是非 bytes 对象，`bytes()` 安全转换。
   - `_uuid_hex` 对异常 uuid 返回 '?' 不崩溃。

**协议层兼容（bms_protocol.py）**：锂安 BMS 对 0x0804 设备信息区响应非标：功能码回显 0x00（非 0x03）、起始地址不回显（0x0000），帧结构仍为扩展格式。`expected_read03_length` / `parse_read03` 接受 fc∈{0x03,0x00}；bms_client 地址校验对 rstart==0 宽容。

**验证结果**：仪表盘稳定输出（50.18V / SOC 64% / 13000mAh / 13 串三元锂 / 温度 26℃），设备信息大部分读出（SN/厂商型号/客户型号/版本日期/BT 码）。

**遗留（非通讯问题，需对照小程序源码确认地址映射）**：read_device_info 中 BMSID=--、循环次数 18505、满充容量 1246448717 mAh 明显错误——0x0804 区域实际是 BT 码 ASCII 区，cycle_count/full_charge_cap 等数值不在此区，寄存器地址映射待核对。

## 遗留问题修复：0x0400 / 0x0804 地址映射弄反（已解决）

**根因**：对比小程序 `battery-info.js` 的 `i()` 函数发现，source="device" 映射到 record 数据块（0x0804），source="record" 映射到 device 数据块（0x0400）。Python 代码直接按变量名望文生义，把两个块的解析弄反了：
- 0x0400 (1024) 实际是**循环记录区**（循环次数/满充容量/闲置时长/BT 码），不是 BMSID
- 0x0804 (2052) 实际是 **BMSID ASCII 区**，不是循环记录

**修复**：`bms_client.py` `read_device_info()` 交换 dev/rec 两个块的解析：0x0400 块读 cycle_count/full_charge_cap/idle/bt_code，0x0804 块读 BMSID。同步更新 README 寄存器映射表和注释。

**实测验证（已通过）**：上传修复后 bms_client.py，ESP32 运行 65 秒：BMSID=FGHIJKLM（出厂测试数据）、SN=LA2601090001、循环次数=4 次（原 18505）、满充容量=13000 mAh（原 12 亿）、BT 码=BT123456789ABCDEFGHIJKLM，全部正确；仪表盘 17 次轮询稳定无超时无重连。BMSID/BT 码内容为出厂测试填充值。串口采集方式：pyserial 发 Ctrl-C+Ctrl-D 软复位后读 65s（mpremote repl 需交互终端，非交互场景不可用）。

**环境变化**：ESP32 串口由 /dev/cu.usbserial-53100033101 变为 **/dev/cu.usbmodem1101**（USB 重插后系统重新分配，USB JTAG_serial debug unit，MicroPython v1.28.0 / IDF v5.5.1 / ESP32C3）。
